# The Shrug catalog

The catalog lists the releases `shrug up` can install. It is signed and
published separately from the binary, so engine releases move faster than
Shrug itself.

## Files

- `catalog/releases.json` — the source of truth, edited by hand and reviewed.
- `catalog/launchers/*.sh` — the per-release start scripts, vendored verbatim
  from the qualifying release (or written by Shrug, like `atlas-gb10.sh`).
- `catalog/catalog.json` — generated by `shrug catalog build`: the same
  document with each release's `launcher` gaining `script` (the file's full
  text) and `sha256`. Deterministic; `shrug catalog build --check` fails in
  CI when it is stale. Committed, and embedded in the binary.

## Document

```
schema:    "shrug.catalog/v1"
serial:    integer, monotonically increasing
defaults:  cluster size (1-4) -> release id
releases:  [ release, ... ]
```

Each release records:

- `id`, `name`, `summary`, `model_id`, `context_tokens`, `concurrency`,
  `role`, `qualified_by`, `notes`, `receipts` (links to the qualifying
  results), `source` (product, url, repo, commit).
- `sparks` and `topologies` (`single`, `pair`, `chain`, `ring`) it fits.
- `engine`: container `image` pinned by digest, `atlas_repo`, `atlas_commit`.
- `weights`: `repo`, immutable `revision`, `size_gib`, `license`,
  `license_url`, `noncommercial`.
- `extra_disk_gib`: on top of the weights (first-start artifacts).
- `launcher`: `file`, `origin`; `script` and `sha256` are added by `build`.
- `container_name`: a template (usually `shrug-rank{rank}`).
- `api_port`: the engine's loopback port on rank 0.
- `args`: the launcher argument template (below).

## Arg templates

Each entry is a string, or an optional flag object:

```json
"--leader-address", "{leader_address}",
{"flag": "--left-hca", "value": "{left_hca}", "optional": true}
```

Every `{placeholder}` is substituted; an unknown placeholder is an error. An
optional object renders as `flag value`, or nothing when the rendered value
is empty. Placeholders:

- `{rank}` — 0-based rank; rank 0 is the machine Shrug runs on.
- `{topology}` — `single`, `pair`, `chain` or `ring`.
- `{leader_address}` — rank 0's fabric IPv4: the lowest-subnet rail for a
  pair, or the first rank-0 address every rank can ping for four Sparks.
- `{fabric_interface}` — this rank's netdev toward the leader.
- `{fabric_hca}` — this rank's HCA on the TP2 rail.
- `{left_hca}`, `{right_hca}` — this rank's comma-joined HCA lists toward
  the previous/next rank (empty at chain ends).
- `{model_root}` — `$HOME/.shrug/models` on that rank.
- `{image}` — the release's pinned engine image.
- `{name}` — the rendered `container_name`.
- `{cuda_cache}`, `{ple_cache}` — `$HOME/.cache/atlas-cuda` and
  `$HOME/.cache/atlas-ple` on that rank.

## Signing

`shrug catalog sign --key-env VAR` signs `catalog/catalog.json` with the
base64 Ed25519 secret in `VAR` and writes `catalog/catalog.json.sig`. The
binary pins two public keys (`src/keys.rs`) so one can be rotated; a remote
catalog must verify against one of them, match the schema, and carry a
serial at least as high as the embedded and cached catalogs. On any failure
Shrug falls back to the cache, then the embedded copy.
